# 여백 · 집필 스튜디오

여백은 표지와 책 판형을 고르고 장별로 원고를 쓰는 한국어 편집기입니다. 로그인하면 서재, 장 구성, 편집 서식, 마지막 작업 위치를 서버에 자동으로 저장합니다. 다른 기기에서 같은 사이트와 계정으로 로그인하면 이어 쓸 수 있습니다.

## 시작

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm run dev
```

서버는 기본적으로 3000번 포트를 사용합니다. `npm test`는 별도의 임시 데이터베이스에서 계정 분리, 기기 간 복원, 동시 수정 충돌과 서버 재시작 후 저장을 확인합니다.

## 집필

- 로그인하고 **신규 작성**에서 에세이, 소설, 시집, 논픽션 서식을 고르고 판형과 표지를 지정합니다.
- 편집기에서는 글꼴, 크기, 자간, 행간, 문단 간격, 정렬, 들여쓰기를 선택한 글자 또는 문단에 적용합니다. 자간, 행간, 문단 간격, 첫 줄 들여쓰기 메뉴에 현재 값과 기본값이 표시됩니다. **판형 설정**에서는 전체 책의 판형, 여백, 기본 본문 서식, 페이지 번호 위치를 바꿉니다.
- 상단 **맞춤법**을 켜면 현재 장의 철자와 자주 틀리는 띄어쓰기를 검사해 빨간 물결 밑줄을 표시합니다. 한국어 사전 검사에는 브라우저 내에서 Hunspell을 사용합니다. [오픈소스 고지](public/spelling-licenses/notice.txt)
- 상단 화살표나 **Ctrl+Z**, **Ctrl+Shift+Z**(Mac은 **⌘+Z**, **⌘+Shift+Z**)로 본문, 장 구성, 판형, 메모와 표지 등 편집 사항을 변경 순서대로 실행 취소하거나 다시 실행합니다.
- **Ctrl+S**(Mac은 **⌘+S**) 또는 저장 상태 옆 아이콘으로 즉시 저장합니다. 편집 영역 오른쪽 아래에서 화면 배율을 조절합니다.
- **표지 편집**에서 손그림을 그리고 사진이나 제목, 저자명 레이어를 배치합니다. 편집 도구 막대의 사진 아이콘으로 본문에도 사진을 넣고 정렬과 크기를 조정할 수 있습니다.
- 기본 화면은 **양면 보기**입니다. 새 장은 다음 쪽에서 시작하고 쪽 번호가 이어집니다. 상단 **단면 보기**로 보기 방식을 바꾸거나, 다른 장의 제목을 눌러 해당 장을 편집할 수 있습니다.
- 원고 구성의 **장 번호·제목 편집**에서 윗줄과 아래 제목의 문구, 정렬, 크기, 글꼴, 색을 각각 설정합니다. **장 제목 삭제**로 제목과 그 여백을 없애고 본문을 이어 쓸 수 있습니다.
- 오른쪽의 **메모**, **등장인물**, **연표**, **복선** 도구는 **Alt+Shift+1~4**로 열 수 있습니다. 도구에서 관련 장으로 이동할 수 있고, 정보는 계정에 비공개로 저장됩니다. **Alt+Shift+F**는 집중 모드를 전환합니다.
- **인쇄·내보내기**에서 원고의 판형, 여백, 본문 서식을 적용해 인쇄하거나 출판사 전달용 본문·표지 PDF로 저장할 수 있습니다. 전자책용 EPUB에는 앞표지와 목차가 포함됩니다. **표지·책등**에서 책등의 너비와 문구를 설정합니다.
- 예제 책을 열거나 즐겨찾기에 추가하려면 로그인해야 합니다. 이 브라우저에 남아 있는 기존 게스트 원고는 로그인 후 계정에 저장됩니다. 두 기기에서 같은 원고를 수정하면 저장된 버전을 열거나 내 수정본을 별도 책으로 보관할 수 있습니다.

## 리더와 공유

- 편집기에서 **초고 완료**를 누른 뒤 **리더에서 읽기**로 책을 엽니다. **집필 중으로 되돌리기**로 상태를 바꿀 수 있습니다. 리더는 책장 넘기기, 목차 이동, 글자 크기·배경 설정과 마지막 읽은 위치를 제공합니다. 리더 홈에서 받은 EPUB 파일도 열 수 있습니다.
- **공유**에서 링크를 만들면 받는 사람이 로그인 없이 읽을 수 있습니다. **공유본 업데이트**로 수정분을 반영하고, **공유 중지**로 링크를 닫습니다. 집필 중으로 바꾸거나 휴지통으로 보내면 기존 링크도 닫힙니다.

## Cloudflare 자동 배포

GitHub `main` 브랜치에 연결된 Cloudflare Workers 프로젝트 `timeline`으로 배포합니다. 빌드가 성공하면 `dist/index.html`과 편집기 파일이 서비스되고, 같은 주소의 로그인 및 저장 API는 Cloudflare에서 실행됩니다. 계정과 원고는 SQLite 기반 Durable Object `YeobaekLibrary`에 보관합니다.

| Workers Builds 설정 | 값 |
| --- | --- |
| 프로덕션 브랜치 | `main` |
| 루트 디렉터리 | `/` |
| 빌드 명령 | `npm ci && npm run build` |
| 배포 명령 | `npx wrangler deploy` |

`npm run dev:worker`로 Cloudflare 런타임에서 실행할 수 있습니다. `npm run test:worker`는 로그인, 서식 있는 긴 원고의 저장 및 복원, Workers 재시작 후 데이터 유지를 임시 저장소에서 검증합니다. 배포 파일은 `npm run deploy:check`로 확인할 수 있습니다.

## Node.js로 직접 운영

한 서버에서 앱과 API를 함께 서비스합니다. 서버를 배포할 때 고정 HTTPS 주소와 재배포 이후에도 유지되는 데이터 디렉터리가 필요합니다.

```sh
npm ci
npm run build
DATA_DIR=/path/to/persistent-data PORT=3000 COOKIE_SECURE=1 npm start
```

HTTPS를 처리하는 역방향 프록시를 이 프로세스로 연결하세요. 신뢰하는 프록시 한 대만 통해 앱에 접속하는 구성이라면 `TRUST_PROXY=1`로 클라이언트 IP를 전달할 수 있습니다. 별도 저장 경로를 지정하지 않으면 `data/studio.sqlite`에 저장합니다.

Docker에서도 실행할 수 있습니다. 프록시는 예시에서 호스트의 3000번 포트로 연결합니다.

```sh
docker build -t yeobaek .
docker run -d --name yeobaek --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -v yeobaek-data:/data -e COOKIE_SECURE=1 yeobaek
```

서버 상태 확인 경로는 `/api/health`입니다. SQLite 데이터 경로를 한 서비스 인스턴스에 연결하고 정기적으로 백업하세요.
